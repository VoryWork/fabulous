# ADR-0004：时间轴对齐的权威来源，以及「拍是时刻」

> 状态：**已决定**
> 日期：2026-11-01
> 关联：`client/src/timeline/domain/TempoMap.ts`、`client/src/App.vue`、`neural/analyze_song.py`
> 触发：用户反复报「小节漂移 / 第一拍是军鼓 / 有时候对有时候滞后两拍」

---

## 1. 问题

对齐问题连续排查了很多轮，每次都「修好了」，但换一次重启或重新播放又出现。
根因不是一处 bug，而是**几个独立的概念错误叠在一起**：

| # | 错误 | 表现 |
|---|---|---|
| 1 | 在第一个 downbeat 前**插入虚拟小节** | 「第一条竖线不是第一拍」，整体偏 1 拍 |
| 2 | `TempoMap` 的 `secToTick` 漏减 `startSec` | tick 0 = 0.10s，但 0.10s 反算回 144 tick |
| 3 | 存在一个**不可见开关**切换两套时间换算 | 「有时候对，有时候滞后两拍」 |
| 4 | 用「和弦块（区间）」判断对齐 | 块左边界对、右边界又偏，看不出真正错位 |

---

## 2. 决策一：拍是**时刻**，不是区间

用户的原始纠正（ASCII）：

```
|-|-|-|-
  ↑     ← 拍是这些竖线所在的时刻，不是每个 |---| 那个矩形
```

因此：

- **绝不在两个真实拍之间凭空插入一个"拍"**。插入一个时刻 = 后面所有拍的
  **序号**整体后移一位。这不是时间漂移，是相位/序号错乱，用户看到的就是
  「第一条竖线不是第一拍」。
- 插入的那个时刻**不是模型检出的拍，不代表任何真实击打**。为了「谱面别空着、
  光标别卡在左边」而伪造一个拍，是拿正确性换观感。
- **前奏该空着就空着**：第一个真实拍就是第 1 拍，谱面左边留白、播放到第一个
  小节前光标停在起点 —— 这是正确的代价。

> 已删除的实现：`realData.ts::padLeadingBar`、`analyze_song.py` 里补虚拟小节的
> 代码块、以及对应的 6 个测试。撤销时同步清理了当时已被写入的
> 《何なんw》数据（121 → 120 小节）。

### 推论：判断对齐要看竖线，不看块

用**和弦块**判断对齐是错的 —— 块可以左边界对齐、右边界又偏。
正确做法是看**某条网格线所在的时刻，音频里是不是一次击打**。

最有效的验证手段：把网格画在波形上（matplotlib 竖线 + `librosa.load` 波形），
一眼能看出橙线是否压在尖峰上，比任何统计指标都直观。

## 3. 决策二：时间换算只有**一个**权威来源

### 现状的两套网格（问题）

| 用途 | 数据源 | 性质 |
|---|---|---|
| 谱面、和弦块 | `beatsSec` / `downbeatsSec` | 真实拍点（有 ±2% 抖动） |
| 播放头、seek | `tempoMap` | 全曲一个平均 BPM 均匀推进 |

只要两者不同源，偏差就**随播放位置累积** —— 表现为
「开头几小节看着对，越往后越偏」且「从不同位置开始播，偏差量还不一样」。

### 决定

**`tempoMap` 只用 `makeRealTempoMap`**：把每个小节的**实际时长**换算成
该小节的 BPM，于是

```
tickToSec(k × 3840) === downbeats[k]     （严格相等，实测全 121 小节误差 0）
```

同时**删掉 `tempoEdited` 开关**。原设计是「用户改过 BPM 就改用
`makeTempoMapFromSegments`（均匀推进）」，但那个状态**在界面上不可见**，
一旦被打开，时间换算就悄悄换成另一套网格，极难排查。

改 BPM 仍然更新速度轨的**显示值**，但不再影响 tick ↔ 秒。
理由：用户要的是「这段听起来是 120」，不是「让播放头偏离原来的声音」。

### 推论：`sec ↔ tick` 必须严格互逆，尤其 `startSec != 0` 时

`TempoMap.startSec` 表示「tick 0 对应第几秒」。修之前有三处漏了它：

```ts
// 修之前
if (points.length === 1)  return Math.round(sec * tps);        // ✗ 漏 startSec
if (sec <= points[0].sec) return Math.round(sec * tps);        // ✗ 漏 startSec
```

于是 `tickToSec(0) = 0.10s` 但 `secToTick(0.10) = 144 tick`。
`startSec` 一直是 0 时不暴露，加了「补虚拟小节」把它变成 0.10 之后就显形了。

回归测试：`TempoMapSymmetry.spec.ts`（13 例，含往返一致、空态、多锚点）。

## 4. 决策三：`createTempoMap` 的非法输入必须在该函数自己兜住

`createTempoMap` 遇到非法输入**直接抛 `RangeError`**，而 Vue 的 computed 抛错
= **整页白屏**。歌还没分析完时三条同时成立：

```
downbeatsSec = []      → (0-1)×3840 是负数 tick，assertTick 抛
meta.bpmMedian = 0     → 「bpm 必须为正有限数」
song.durationSec = 0   → 「durationSec 必须为正有限数」
```

`makeTempoMapFromSegments` 本来有兜底，`makeRealTempoMap` 没有 —— 换实现时
**只看了主路径逻辑，没注意它兼着防御职责**，结果一换就白屏。

决定：

- 兜底写在 `makeRealTempoMap` 内部（`downbeatsSec ?? []`、`bpmMedian > 0 ? : 120`、
  `durationSec > 0 ? : 1`，`d.length < 2` 时退回单锚点）。**不能指望调用方**。
- `tempoMap` computed 外面再包一层 `try/catch`，失败退化成「120 BPM 空白时间轴」。
  白屏是最糟的失败方式 —— 用户看不到任何信息，也没法自己恢复。

## 5. 决策四：模型输出进入渲染前必须「排序 + 去重叠」

用户要求「结构段不能叠」。模型（all-in-one-infer）输出的段落
**既不保证有序，也不保证不交叠**，直接画会出现两条结构块压在一起。

`normalizeSections` 现在统一收口四件事：排序 → 去重叠（起点推到上一段末尾）
→ 丢弃被完全吃掉的段 → 合并相邻同名段。

同时 `createAt`（新建块）也必须遵守 `allowOverlap: false`：
拖动手势有 `validateClipChange` 把关，但**新建走的是另一条路**（直接 push），
原来完全没有检查。现在的策略不是「重叠就拒绝」（点了没反应很困惑），
而是**往后找最近的空位**并自动收缩长度。

## 6. 已知的正常「不对齐」

不是所有偏差都是 bug。以下属于预期行为，不要试图"修"：

- **散板前奏**：没有鼓组，模型只能瞎猜。实测《何なんw》5.42s 的 downbeat
  落在波形间隙里，且 `5.42 → 7.46` 只有 2.04s（其余小节 2.66s）。
  `fixDownbeats` 阈值是 0.55 倍中位，0.77 倍正好躲过，所以不会被修。
- **远程桌面**：RDP 会把 `requestAnimationFrame` 节流到 10~20fps，而音频时钟
  是连续的 —— 播放头按帧跳，听感上就会拖后。这种情况下换算层是自洽的
  （见下面的诊断），差异只来自渲染帧率或音频设备缓冲。

## 7. 诊断手段（保留在代码里）

右下角开发角标显示三件事：

```
第 41 小节 · ♩=90.2 · tick 155081 · 109.81s · map 109.81s · 起点 2.76s
                                     ↑ 引擎回报  ↑ tempoMap 反算
```

| 现象 | 结论 |
|---|---|
| 两个秒数**相等** | 换算自洽，问题在渲染/播放层（帧率、设备缓冲） |
| 两个秒数**不等** | tempoMap 与播放头不是同一套换算 |
| `起点` 变了 | `data` 被重建（HMR / 重新加载），谱面换了网格 |

命令行诊断脚本（都只读，不改数据）：

```bash
python -u neural/check_groove.py  <song_id>   # 鼓组相位：底鼓在 1/3 拍、军鼓在 2/4 拍
python -u neural/check_energy.py  <song_id>   # 小节线处的 onset 强度
python -u neural/check_grid.py    <song_id>   # 小节时长分布 / 和弦距小节线拍数
python -u neural/verify_all.py                # 对 DB 里所有歌做六项体检
```
