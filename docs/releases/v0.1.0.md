# v0.1.0 — 首个可分发版本

**Windows 10/11 x64 · 解压即用 · 无需安装任何运行时**

分析全程在本地跑（ONNX + Rust），**不上传音频、不联网、不需要 Python**。

## 能做什么

**自动分析一首歌**（4 分钟约 20 秒）：

- 拍点与小节网格（含拍号推断）
- 和弦（三个词表档位：`submission` / `ismir2017` / `full`，可随时切换）
- 段落结构（Intro / Verse / Chorus …）
- 调性推断 + 录音音高偏差校正（跑调/移调录音也能对上）

**然后当成编辑器用**（这才是重点，模型只负责铺 90%）：

- 和弦块：拖动、切分、合并、改文本；和弦可以带性质与转位（`D:maj/3`）
- 结构段：增删改、拖动边界
- 级数轨：按 `1 5 6 4` 看和声走向，跟随调性自动换算，父和弦一改就跟着更新
- 歌词轨：导入 LRC（标准格式或网易云 JSON），吸附拍点，逐行可编辑
- 波形、循环区间、点击定位、播放头同步
- 撤销 / 重做

**编辑和模型结果分开存**：`analysis.json`（模型产物，重新分析会覆盖）和 `edits.json`（你的修改，
永不覆盖）。所以「重新分析把我的手改冲掉了」这件事不会发生。

**工程文件 `.fbsong`**：纯文本 JSON（分析结果 + 编辑层，一个字段不裁，不含音频），
换机器、分享、归档都靠它。导入后如果音频不在原位，会按音频指纹让你重新定位。

## 支持格式

flac / mp3 / m4a(aac) / ogg(vorbis) / wav

## 已知限制

- **仅 Windows x64**（macOS / Linux 未构建，代码上应该可行但没验证）
- 拍号与速度是推断值，非常规节奏（自由速度、复合拍）需要手动核对
- 结构边界对「渐变式过渡」的判定不稳定，这类段落建议手改
- 首次分析要加载模型，比后续分析略慢 1~2 秒
- 音频文件本身不入库、不上传：软件只读取本地文件

## 数据位置

```
%APPDATA%\com.xmmpp.client\
  musicanaz.db              曲库索引
  songs\<id>\analysis.json  模型产物
  songs\<id>\edits.json     你的编辑
```

卸载/重装不会丢（升级也不会，只要不手动删这个目录）。

## 模型致谢

分析能力来自以下开源项目，权重已导出为 ONNX 随本软件分发：

- [beat_this](https://github.com/CPJKU/beat_this) — CPJKU，拍点与小节
- [lv-chordia](https://github.com/openmirlab/lv-chordia) — OpenMIR，和弦识别（5 折 + XHMM）
- [all-in-one-infer](https://github.com/openmirlab/all-in-one-infer) — OpenMIR，段落结构

请遵守各项目自身的许可证。

## 反馈

和弦识别错、结构切得不对、界面卡顿都欢迎反馈。
**附上歌曲的流派/编配信息比附音频有用**（音频我们收不到也不该收），
如果是特定类型的歌（爵士、自由速度、无鼓、现场版）识别差，说一声好定位。
